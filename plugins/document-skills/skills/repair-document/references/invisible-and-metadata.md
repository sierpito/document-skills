# Invisible characters, provenance metadata and report discipline

Approaches taken from the open-source `watermarks-remover` project, limited to what is deterministic
and verifiable. Its statistical text-watermark rewriting, back-translation, pixel/audio removal and
"avoid the vendor's own model" tactics are not part of this skill (see `SKILL.md`, "Refuse").

## 1. Inspect first, with confidence labels

Run `scripts/invisible_chars.py <file>` (read-only) before any cleaning. Each class gets a label:

| Label                 | Meaning                                 | Example                                                                                                                      |
|-----------------------|-----------------------------------------|------------------------------------------------------------------------------------------------------------------------------|
| confirmed             | never legitimate in reader-facing text  | zero-width space, tag characters (U+E0000-E007F), BOM mid-text                                                               |
| probable              | usually an artifact, sometimes intended | bidi controls in LTR text, variation selectors, typographic spaces U+2000-200A, Cyrillic/Greek lookalikes inside Latin words |
| informational         | report only, kept by default            | soft hyphen, NBSP and narrow NBSP (units, French punctuation), ZWJ/ZWNJ near emoji or non-Latin script                       |
| likely_false_positive | looks suspicious, is correct            | ZWJ in an emoji sequence, bidi controls in Arabic/Hebrew text, NBSP between a number and a unit                              |

Put the table, with counts, at the top of Findings. Do not call any of it a "watermark": say
"invisible characters" and let the user decide what they mean.

## 2. Clean deterministically, around protected spans

`scripts/invisible_chars.py <file> --clean --out <working-folder>/out/<name>` writes a new file, never
overwrites, never touches the input. It:

- removes confirmed classes, bidi controls outside RTL text, soft hyphens and variation selectors;
- turns U+2000-200A, U+205F, U+1680, U+3000 into a plain space; keeps NBSP and U+202F (they carry meaning);
- replaces lookalike letters only inside words that already contain Latin letters;
- skips fenced and inline code, URLs and `script`/`style` blocks in text files; in .docx/.pptx it edits only
  text nodes inside `word/`, `ppt/` and `docProps/`, and repacks in the input's member order.

Run it again on the output and expect zero confirmed findings. Do not apply NFKC unless the user asks:
it changes ligatures, fractions and superscripts that are real content.

Never touch: code, commands, paths, URLs, identifiers, formulas, citations, required disclosures,
verbatim quotations. Never translate. Never invent facts, names, quotes or sources: flag gaps instead.

## 3. File metadata beyond the OOXML core

| Where          | Inspect                                                                                                               | Notes                                                      |
|----------------|-----------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------|
| DOCX/PPTX      | `docProps/core.xml`, `app.xml`, `custom.xml`, comments, alt text                                                      | covered in `detect-pptx.md`                                |
| ODT/ODS/ODP    | `meta.xml` (`generator`, creator, dates)                                                                              | same rules as OOXML properties                             |
| PDF            | `pdfinfo` (Author, Creator, Producer, dates), XMP packet, embedded files (`pdfdetach -list`), embedded image metadata | rewriting a PDF invalidates digital signatures: warn first |
| Images         | EXIF Software/Make, XMP, IPTC, PNG text chunks (`parameters`, `prompt`), C2PA/JUMBF                                   | read locally with Pillow or `strings`; upload nothing      |
| LaTeX/Markdown | `\hypersetup`, `\pdfinfo`, front matter, HTML comments such as `<!-- generated by -->`                                | the compiled PDF is a separate file                        |

Policy:

- **Disclosures stay.** C2PA manifests, IPTC `DigitalSourceType` and any statement that content is
  AI-generated or AI-assisted are provenance disclosures: report them, do not strip them.
- **Hygiene fields may go, on an explicit ask for that file:** prompt or parameter text in PNG chunks,
  tool/version stamps in `Producer`/`Software`, placeholder authors and dates (set to confirmed values),
  editor modelines. Say which were removed.
- Keep non-AI camera and editor metadata unless the user says otherwise.
- PDF caveats to report: without `exiftool`/`qpdf` cleaning is partial; recompressing embedded JPEGs is
  lossy; leave image streams byte-identical unless asked.
- If a destination demands disclosure (academic, regulated), do not remove anything that discloses.

## 4. Directories and batches

For several files or a folder, inspect each, then print one summary and exit with: `0` nothing
actionable, `1` actionable findings, `2` usage error or refusal, `3` partial scan (some files unreadable,
encrypted or too large). Treat `3` as inconclusive, never as clean.

## 5. Report discipline

Split the report into three blocks and never blur them:

1. **Verified changes** - counts from the script and from diffs (characters removed, properties set).
2. **Best-effort changes** - anything judged rather than measured (notes rewritten, wording condensed).
3. **Out of scope / residual** - what was not looked at (audio, video, soft-bound C2PA, secret-key or
   vendor-side marks) and what may still be detected.

State that repair is not proof of human authorship and does not make a file "undetectable".

## 6. Optional guardrails

- A `PostToolUse` hook or pre-commit hook that runs `invisible_chars.py` in inspect mode on files the
  agent writes, failing on `confirmed` findings, catches stray invisible characters early. It is a
  suggestion for the user to set up; this skill does not install hooks.
